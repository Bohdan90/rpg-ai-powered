## Launch

1. Open this repository's Unity project (`My project`) in **6000.6.2f1**.
2. Open `Assets/_Project/Scenes/TacticalGraybox.unity` and press Play.
   Alternatively choose **Gate C → Play Tactical Graybox**.
3. Use a large Game view (maximize its tab); 1440×900 or larger is recommended.
   The entire board fits the fixed orthographic camera. The HUD scrolls when needed.
4. The current actor is automatically selected. Green cells come from Core path queries.
   Click a destination or target, inspect the preview, then click **Confirm selected Move / Attack**.
5. **Defend** and **End Activation** submit Core commands directly. Both sides are local hotseat.
   Optional **End facing** uses the existing Core EndActivationCommand field.
6. **Restart Same Seed** resets the selected map, armies and RNG. **Map** selects BaseMap or
   ControlMap and resets. Allied targets require the explicit confirmation checkbox.

No component attachment, camera setup, UXML authoring, asset import or manual scene setup is required.
The editor menu **Create or Open Tactical Graybox** can recreate the minimal scene through Unity's
scene/asset APIs and repair its serialized panel/shader references. Scene YAML was generated by Unity.
SampleScene remains in Build Settings; open TacticalGraybox explicitly for Play Mode.

## Appearance and interaction

Top-down fixed orthographic board, x increasing right and y increasing upward. Dark alternating cells,
three taller gray obstacle cells, blue West and orange East tokens. HW cylinders, HA cubes, EW spheres;
white facing arrows and a gold active marker. Overlays show side/profile, Commander star and HP/Armor.
Hover and the HUD identify the named unit. Reachable cells are green; selected path cells/line are gold.
The right-hand scrollable panel shows the active unit, round, full live initiative order with current marker,
resources, Defending, hover/selection, Core previews, controls, rejection messages and 24 recent Core events.
Positions snap only after accepted Core movement. No animation timing affects rules.

Legal attack previews show effective range, LoS/corner status, contact and separate eligible Guard chance,
physical damage on an unguarded hit, Armor/HP loss, Frontal Evasion and Steady Aim. Illegal previews display
Core's reason; unavailable chance/damage fields are not invented. Path failure reasons are shown where
Core exposes them; otherwise the HUD says no executable path within remaining Movement.

## Assumptions, deviations and limitations

**P — PROTOTYPE ASSUMPTION (presentation only):** fixed seed `20260921`; IDs 1–5 West and 6–10 East;
Commander is a display marker for the two contract HW Commander IDs. BaseMap is the default; changing map
resets instead of preserving a running battle. Top-down primitives, snapshot snapping and a 24-event display
are local graybox choices, not gameplay canon. There are no new combat assumptions or rule deviations.

The existing optional final-facing Core field is executable through the HUD; it is not deferred.
No ZoC/OA, retreat/escape execution, victory flow, AI, deployment editing, telemetry/export, persistence,
abilities, animation, audio or external art was added. Outer columns remain ordinary cells as in M2A.
The contract's later OA/deployment/retreat/export controls remain deferred by this milestone's explicit scope.
HP/Armor use numeric labels rather than finished bars; this is the requested minimal graybox presentation.

No known blocking graybox bug remains after validation. The HUD needs scrolling at smaller Game view sizes;
use a maximized view for readability. In this installation the pre-existing Unity AI package logs
`NoSubscription` / entitlement errors in the Editor, unrelated to Core/Presentation. Packages were not changed
or modernized to hide those errors. They did not block the live combat loop or test suites.
